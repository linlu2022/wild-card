# 角色 wildcard 质量改进方案与鲁棒性推演

日期：2026-09-26。基线：提交 `7650f50` 的十套角色词库，共 1,894 行。

状态：**方案已完成并留档；词库迁移和生产流程改造尚未实施。** 本次推荐版本为 v2.3，表示下文四轮设计推演后的方案版本，不是节点版本。这里只能确定它最适合当前目标与已知约束，不能证明存在一个适用于所有模型、所有作品的全局最优方案。

推荐采用：**角色与形态登记表 → 按特征保存证据 → 审核状态控制导出 → 分版本发布。** 自动化负责发现、整理、检查和导出；角色归属、形态对应和具体外观必须有可追溯的审定依据。未知信息保留为未知，审定通过的少量特征也可以输出。

## 1. 目标、约束与本次交付

已由用户确认的范围：女角色；尽量覆盖；服装／皮肤变体独立保留；Fate 仅 FGO；初音系列为 VOCALOID 声库角色及其形态。节点继续接收文本框里的 wildcard prompt，只输出一个展开后的 STRING，保留 seed 和预览功能。

质量优先级建议：错误身份／作品归属与串入他人外观最先处理；随后是形态混淆、缺失覆盖、重复与抽样分布。一次错误不能靠更多正确条目在平均分里抵消。

本次交付包含：

- 四类候选方案的比较和四轮优化记录。
- 可执行的入库规则模型、34 个场景和 10 个字段缺失检查。
- 对当前采集、颜色处理、wildcard 展开及本机 ComfyUI 文本解析函数的离线反例验证。
- 当前文件散列、十套旧采集资料的计数摘要、迁移顺序与验收标准。

推演入口：[evaluate.py](../curation/design-v2/evaluate.py)；运行结果：[results.json](../curation/design-v2/results.json)；旧采集摘要：[legacy-evidence-summary.json](../curation/design-v2/legacy-evidence-summary.json)。它们是方案证据，不能当作 1,894 条已通过逐图审定的证明。

## 2. 先纠正审计本身

上一轮把 Circe、三月七、梅莉的多眼色列作冲突，理由是没有 `heterochromia`，这个判断不成立：

| 词条 | 文件行号（基线版本） | 已存在的标记 |
| --- | ---: | --- |
| `circe_(fate)` | FGO 54 | `multicolored_eyes`, `two-tone_eyes` |
| `march_7th_(honkai:_star_rail)` | 星铁 44 | `multicolored_eyes` |
| `maribel_hearn` | 东方 77 | `multicolored_eyes`, `two-tone_eyes` |

这些词条应撤销“仅因两个颜色而冲突”的告警。两个眼睛颜色不同、同一虹膜内部多色、光照差异是不同现象；最终仍要验证颜色位置和对应形态。发现标记不意味着已经证明颜色正确，缺少某一个标记也不意味着错误。

同样，`short_hair + medium_hair` 应先视作长度边界或画风差异的待核项；`long_hair + very_long_hair` 常为上下位标签，不能硬判冲突。标签相同也不能证明人物相同。

旧绝区零资料中的“23 条没有单角色图”应准确表述为：**18 条记录为零，另 5 条缓存没有保存该字段**。缺失数据与观察到零是不同状态。共 32 条采用全部官图回退的计数仍成立。

## 4. 候选方案比较

| 方案 | 做法 | 优点 | 关键失败场景 | 结论 |
| --- | --- | --- | --- | --- |
| A：修黑名单与统计阈值 | 删除已知误收，提高官图数量和频率门槛 | 修改少，能快速止住已知错误 | 新玩偶、新别名继续漏过；冷门角色误删；同一错误被转载仍可过阈值 | 适合止血，不宜作为质量依据 |
| B：只用严格单标签官图 | 不回退普通作品，要求固定数量的单角色官图 | 群像串色减少，规则容易解释 | 一张清楚的官方立绘仍被拒；官方基础名与皮肤名常共同出现 | 保留来源优先原则，取消固定张数硬门槛 |
| C：逐图视觉模型直接填写 | 视觉模型看图后生成角色和外观 | 容易理解局部外观和服装 | 容易把拟人图当正典、混淆同脸角色；缺失资料时仍可能补全；跨轮不可复现 | 用于提出与检查特征，不赋予独立裁决权 |
| D：角色／形态／特征证据登记 | 明确实体关系，证据逐特征绑定，状态决定导出 | 能定位误收原因，支持稀缺资料与增量维护 | 前期登记成本较高；错误的人工／模型审定依然会进入系统 | **推荐；加入独立复核、来源留存和发布门槛** |

不做虚构百分比评分。D 的优势来自它能表达 A–C 无法区分的状态：同框与同人、人物与形态、来源标签与已验证来源、未知与明确不符合。

## 6. 推荐的资料结构与处理规则

### 6.1 四种对象，分别回答四个问题

| 对象 | 必需内容 | 避免的问题 |
| --- | --- | --- |
| `entity` | 稳定 ID、规范身份、可见名称、作品登场依据、女性身份依据、实体类别 | 把玩偶或拟人图当作已确认女角色 |
| `form` | 所属实体、具体服装／身体形态、默认或变体、正典依据、适用版本 | Sam／流萤、人形／机器人、默认／泳装串用 |
| `claim` | 具体特征、身体部位、适用形态、证据 ID、观察位置、冲突与审定记录 | 一整张群像的标签被复制给某个人 |
| `export` | 输出作品、实体与形态 ID、目标编码器配置、采用的断言、release ID | 无法解释某行来源，或导出语法产生意外权重 |

别名表把多个来源名称映射到同一个实体与形态；形态表让同一个实体拥有多个正式变体。两者分别记录。官方女性机器人可以收录；已确认的陪同道具不能因为常与女角色同框而通过。这里的陪同道具不包括已确认为女性的伙伴角色：例如“伙伴”身份本身不能成为排除理由。性别／女性身份不从体型或 `1girl` 频率推断。

FGO、VOCALOID、终末地均保存两个字段：`origin_franchise` 与 `appearance_in_requested_work`。作品里正式登场的联动角色与仅在宣传图中同框的角色不能共用一个“版权匹配”结论。官方或标签系统改名只更新映射，不改变稳定实体 ID；涉及身份重释时重新审定。

### 6.2 来源质量与资料稀缺

优先使用可核验的官方角色介绍、设定图、立绘和游戏内资料。Danbooru 提供候选、标签词汇、来源链接与异常提示；`official_art` 和版权共标签不单独承担来源认证。

不再把“至少 3 张／5 张”作为身份真实性或外观真实性的硬门槛。一张清晰且身份、形态已核验的官方设计，可以支撑其中清楚展示的特征；看不到的瞳色不填写。多张不独立的转载不会增加可信度。记录 post ID、原始来源、内容摘要／散列、设计 ID；必要时用近似图像比对协助去重，但近似比对结果仍可复核。

普通作品只能提示查证方向。若身份和女性属性已确认，但只有同人外观：该条可进入可选的 `identity_only` 集，包含已确认的角色触发词，不附带猜测外观；完整外观词库暂不收录。它继续计入“已发现但外观未解决”，避免被静默丢弃。

群像可以用，但必须明确定位目标，并由视觉复核把具体特征关联到目标身体部位。全图的 general tags 不能直接作为该局部特征。基础名与皮肤名共同出现也必须验证目标形态。

来源失效时，已有可追溯、已核验的留存证据可继续支持原结论；只剩一个 URL 且无法恢复证据时，降低该证据的可核验状态。新抓取失败不能把旧记录变成“角色不存在”。

### 6.3 形态与标签

每个形态独立构建特征。默认形态必须绑定默认设计，不能用泛角色标签的全部作品平均出一套服装。

继承仅限已确认在目标形态仍成立的特征。支持 `inherit`、`override`、`remove`，并记录依据；年龄变化、机械化、附身、升阶、换装可能改变原来以为稳定的属性。Magical Mirai／Racing 这类总称须明确具体版本，或者作为下级已审定版本的抽取入口，不能复制一组基础初音标签就宣称完成一个服装版本。

不强行凑满 8 个或 20 个标签。输出少量准确且有辨识度的特征。身体、衣服、附件分别存储，便于将来提供只保留身份特征的输出配置；是否输出胸型、露肤等细节属于用户的提示词风格，不能由热度决定。当前完整组合配置优先输出可验证的外观。

保留真实多色眼、渐变发、挑染等空间关系。冲突条件是“同一形态、同一部位、同一适用状态下，两项断言不能同时成立”。灰白色标注或中短发边界先进入复核；不自动按标签排序选择胜者。不靠增加 `multicolored_*` 来掩盖尚未解释的冲突。

相同标签集合产生提醒，不自动合并。已证实的同身份同形态别名合并出口；已证实不同形态即使暂时提取到相同特征，也应核对差异是否漏提。确实外观等价但身份版本不同的，保留带依据的例外记录。

### 6.4 状态、审批与增量更新

建议状态为 `discovered → needs_review → release_full / identity_only / excluded / merge_reference`。审核人或审核代理、时间、来源与判断理由必须留存。模型生成的描述标记为模型建议；没有相应证据检查记录时不能自标成“人工复核通过”。

以下条件都要满足才能 `release_full`：身份与女性属性已确认；符合选定作品范围；具体正典形态明确；来源身份与形态绑定已核验；导出的每项特征有支持；阻塞性冲突已处理；导出语法适合目标配置。总分或平均置信度不允许补偿任意一个缺失条件。

初次迁移时，全部 1,894 条先建立未审定记录。高风险条目先排队，但低风险条目也必须完成身份、形态和采用特征的依据登记。以后只复核新增或受到来源变化影响的断言；新候选和更新失败不能覆盖上一个已审定发布版本。明确发现旧结论错误时记录勘误与替代版本，不能仅保留已知错误而不告知使用者。

## 7. 34 个场景的规则推演

状态含义：`release_full` 可进入完整外观集；`identity_only` 只具备可选的身份集资格；`needs_review` 暂缓完整导出；`excluded` 按当前范围排除并保留原因；`merge_reference` 保留别名来源而不增加重复出口。

| 场景 | 应有结果 | 主要约束 |
| --- | --- | --- |
| S01 Anastella 已审定为陪同玩偶 | excluded | 女角色共标签不覆盖实体类别 |
| S02 Binah 同人拟人化 | excluded | 同人女性形态不覆盖原始身份 |
| S03 官方女性机器人 | release_full | 不把“非生物”一刀切排除 |

## 8. 系统层面的进一步攻击与防护

下表是架构推演，除已注明者外尚未做生产故障注入。

| 场景 | 脆弱方案会发生什么 | 最终设计 | 剩余限制／验收方法 |
| --- | --- | --- | --- |
| 热门作品超过 API 候选上限 | 截断被误当完成 | 官方可用名单、作品内登场资料、角色标签分页共同发现；记录每入口覆盖与截断 | 没有权威全量名单时只报告“已核对范围”，不得声称全收录 |
| 新角色尚无 Danbooru 标签 | 被彻底漏掉 | 登记实体与官方证据；触发词可用性单列待测 | 暂不虚构规范 tag；按模型配置测试已知名称／文字描述 |
| 一张官方设计被大量转载 | 数量制造置信假象 | post、图片、设计三级计数；来源去重 | 近似图像去重也会误合并，需记录可撤销决定 |
| 同一人近期泳装作品占多数 | 默认服装变泳装 | 先指定形态再采证，按官方设计取样 | 旧模型可能仍偏好热门皮肤，另做出图检验 |
| 颜色随光照与画风变化 | 擅自删色或合成不存在的双色 | 以目标设计为基准；保留冲突来源与部位 | 难判的细节可不输出，不能凑数 |
| API 限流、断网、部分下载失败 | 空结果覆盖旧资料 | 有限重试、缓存、断点状态；新批次标记不完整 | 定义失败与“已证实无结果”的区别；保留旧发布版 |
| 别名改名或身份设定更新 | 重复、丢失、历史难追 | 稳定实体／形态 ID，版本化来源映射 | 语义变化需重新审定，不能自动改一个字符串结束 |
| 同作品不同地区进度 | “缺角色”与剧透混在一起 | 来源记录地区、版本、as-of 日期 | 默认资料范围必须明确；用户可要求地区过滤 |
| 多文件发布中断 | 主索引与下级词库版本混用 | 暂存区在扫描目录外；完整验证；不可变版本命名；维护窗口切换并加载验证 | 多次文件替换不等于整体原子事务。执行时需验证实际文件系统及加载器时序 |
| 其他 custom_wildcards 覆盖同名文件 | 测的是 A，运行用的是 B | 使用版本化命名空间，发布后核对实际解析到的键、条数和内容散列 | 当前加载器存在后加载覆盖行为，不能仅检查磁盘文件 |
| 固定 seed 跨版本 | 输出角色变化 | 复现信息包含词库版本／散列、引擎版本、seed、实际 populated prompt | 单有 seed 不足以保证跨版本复现 |
| 引用环、缺文件或非法 wildcard 语法 | 残留引用、提前停止、异常展开 | 发布前图检查：无环、所有引用存在、键符合语法、每条出口可达 | 仍要通过真实项目与 Impact Pack 加载器验证 |
| 模型不认识冷门角色／新形态 | 文本正确但图不对 | 数据验收与出图能力分开；按目标 checkpoint/LoRA 做定向样例 | 不把模型生成图当作角色正典证据 |
| 重复 wildcard 生成多角色 | 重复 1girl、人物混合且无空间关系 | 本批定义为单角色组合；多角色属于另一个组合设计 | 当前引擎无全局去重已实测，不能再承诺自动去重 |

## 9. 输出形式与抽样分布

现有文件名代表“每行一个角色形态，按行等概率”。推荐保留这一已被用户接受的行为，先合并真正的同形态别名，再计数；不悄悄改成按人物等概率。

可以另导出一个明确标名的按人物均衡入口：一级每个实体一行，二级只列该实体已审定的形态。假设有 N 个实体、实体 i 有 k_i 个形态，则人物被选中的概率为 1/N，形态为 1/(N·k_i)。这样增加某人的皮肤不会提高其人物总概率。顶层与子级必须使用独立命名空间并做引用图校验；多个通配模式合并会改变分布，不应宣称仍保持均衡。

同一正式变体可以保留，但多个拼写别名不能成为多个抽签机会。FGO 的 322 行不能解释为 322 名独立女性。

登记表始终保留规范原始 tag。输出配置决定文字格式：传统 ComfyUI 加权文本按需转义字面括号；其他编码器可以选择原始文字。只对标签字面量编码，用户主动写的权重表达式不能全局转义。反斜杠、括号、冒号、`{}`, `|`, `__` 与换行需按“标签字面量”或“受控 wildcard 表达式”类型校验，不能简单字符串拼接。下划线／空格偏好也由配置指定并用实际模型验证，不进行无依据的全局替换。

保持最终输出一个 STRING，不要求运行时访问互联网、角色数据库或视觉模型。

## 10. 建议的收录配置与尚需讨论的偏好

以下是推荐配置，供后续实施时采用或调整；本次留档不改变现有词库内容。

| 项目 | 推荐值 | 理由／可调整部分 |
| --- | --- | --- |
| 身份 | 作品内可确认的女角色，包括正式 NPC、反派和女性机器人 | 不把可玩性或生物属性当硬门槛；未知保留待核 |
| 联动 | 正式在该作品里登场且满足女性身份者可收；宣传同框不直接收 | 和“尽量覆盖作品内角色”相符；来源必须明确 |
| FGO | 登场作品限定 FGO；角色原作可来自其他 Type-Moon 作品 | 是否扩展到仅礼装／宣传画出现的角色需单独列配置；默认不据此认定登场 |
| VOCALOID | 声库角色的正式形态可收，包括明确的官方联动形态 | 不扩展为 Project SEKAI 原创人物全集；每种初音设计要有具体版本 |
| 同人拟人／性转／原创改造 | 进入独立候选池，默认不进本批正式女角色集 | 防止 Binah 类型的误收；以后可另开专门词库 |

这些选择不会阻止先实现登记、证据绑定、格式检查和复核界面。业务范围有歧义的条目保持待审，后续只需调整范围配置，不必重写所有采集逻辑。

## 11. 迁移与验收

建议顺序：

1. 固定旧版散列与来源摘要，把现有文件标为待迁移基线。新版本输出到暂存区，旧版保持可复现。
2. 建立实体、形态、来源、断言、别名与审核记录。先导入旧行及出处，不把旧“reviewed”名称自动升级成审定通过。
3. 用 30 条真实记录做试点：10 条已知高风险、10 条稀缺／形态复杂案例、10 条分作品抽取的普通对照。试点必须包含多色眼、女性机器人、单张官方设计等正常反例。记录单条处理时间、返工原因和来源可获得率，再估算全量成本。
4. 优先核查 Anastella、Binah、Sam，以及绝区零的 32 条全部官图回退、九套 137 条共标签取样、643 条普通作品回退和 2 条盲继承。集合先去重，不能把这些计数相加当成待审总量。
5. 完成其余记录的身份／形态与导出特征审定；将覆盖账中的未解决候选单列，扩展被截断的发现入口。
6. 输出新版 CSV／JSON 与 TXT，完成静态、解析、加载和目标模型样例验证。通过后按作品分批发布不可变版本，记录替代关系与回滚方式。

| 验收层 | 必须提供的证据 | 不足时的状态 |
| --- | --- | --- |
| 身份与范围 | 每条出口的稳定 ID、女性身份、作品登场和形态依据 | needs_review 或按明确原因排除 |
| 外观 | 每项输出特征指向审定证据，未知不填，无未解释的阻塞冲突 | identity_only 或 needs_review |
| 误杀控制 | 复核正常多色、稀缺官图、真实机器人等正向反例；抽查被排除候选 | 纠正规则并保留审计勘误 |
| 独立质量检查 | 高风险记录全部进行第二次证据检查；普通记录按作品和来源分层抽查，初始建议 10% | 发现一类系统性错误时扩大该层检查，不能只改被抽中的那一条 |
| 覆盖 | 参考名单版本、已登记／正式出口／身份集／待核／已排除数量及原因 | 标记 partial，不能称作品全集 |
| 导出 | 规范编码、唯一实体形态出口、CSV/JSON 与 TXT 一致、配置转义、无非法控制语法 | 不发布本批新文件 |
| 加载 | 项目节点与 Impact Pack 实际加载到的键、条数、引用和散列一致 | 保留上一版本 |
| 可复现 | 源资料摘要、政策版本、导出器／引擎版本、词库散列、seed、实际输出 | 标明不能复现的环节 |
| 图像表现 | 使用用户指定或现有已批准的目标工作流，对试点和高风险形态比较输出；记录 checkpoint/LoRA、seed 和提示词 | 标注模型支持限制，不倒推修改正典事实 |

10% 是试点阶段建议的复核抽样比例，不是统计上保证正确率的声明。语义检查记录必须区分人工、模型辅助和自动规则，避免所有阶段由同一次生成自我确认。明确的技术错误可以由执行代理修复；作品范围等偏好由用户选择。

停止条件：本次承诺发布的范围内没有未解决的身份／形态阻塞项；每个实际导出断言可追溯；正常反例通过；格式与加载通过；覆盖缺口被如实列出。部分资料尚未解决时可发布明确标为 partial 的合格子集，不能通过静默删除待核项制造“完成”。

## 12. 复现本次设计验证

从仓库根目录，使用已安装项目依赖 `requests`、`numpy`、`PyYAML` 的 ComfyUI Python：

```powershell
python curation/design-v2/evaluate.py
```

脚本默认从相邻 ComfyUI 目录提取文本解析函数；其他布局可指定 `--comfy-root <ComfyUI目录>`。找不到解析源码会明确记录该项跳过；缺失 Python 依赖会直接失败，请使用现有 ComfyUI 环境。不会联网，也不会生成图片。重跑会覆盖 `results.json`；若要保留历史结果，使用 `--output <新的文件名>`。
